# Learning Loop —— AI 闭环学习技能

> 让 AI 像私人导师一样，**教你 → 测你 → 看你哪里不会 → 重新教你 → 直到你会**，整个闭环可中断、可恢复。

---

## 这是什么

一个把"学习某个技能/领域"变成**可衡量、可追踪、会自适应**的 ZCode 技能。

传统 AI 教学的通病是：生成一堆资料就结束，不知道你到底学没学会。Learning Loop 的不同在于：

- **每个章节都有通过/不通过的硬门槛**（正确率 ≥80%）。
- **不会就重构教材**（不是让你重看，而是 AI 换个角度重新讲），最多重讲 3 次。
- **每章学完生成 wiki**，记录你哪里稳、哪里虚，**指导下一章怎么讲**。
- **中断了能恢复**——下次调用自动接续上次进度。

核心信念：**教学不是生成内容，是确认掌握。**

## 安装与更新

**安装（一次性）**——把仓库克隆到 ZCode 的 skill 发现位置，并装一次 slash command：
```sh
git clone https://github.com/kaikaixiaotian/learning-loop.git ~/.agents/skills/learning-loop
cp ~/.agents/skills/learning-loop/commands/learning-loop.md ~/.zcode/commands/
```
> Windows 用 Git Bash 或 PowerShell 均可，`~` 会展开到用户主目录。

**更新**——在 ZCode 里输入：
```
/learning-loop update
```
会自动从 GitHub 拉取最新代码、更新 skill 本体并同步命令自身（底层 = skill 目录 `git pull` + 复制命令文件）。更新后**新开一个会话**以加载最新版本。

> 学习本身**不需要命令**——直接用自然语言说主题即可（见下方「触发方式」）。`/learning-loop` 命令目前只负责 `update`。

## 学习闭环长这样

```
初始化：描述主题 → AI 出基线测评（15-25题，六类题型）→ 你填写并上传
   ↓
AI 批改 → 【子Agent 从权威源拉取该领域公认学习路径 + 各章资料卡】
   ↓
AI 按你的基线/目标水平「适配」外部路径（拆分/补强/调深度）→ 写总目录 + 第一章教材 + 第一章测验
   ↓
你学教材 → 填测验上传 → AI 当场再追问几个新问题（计划测验，查迁移能力）
   ↓
                    ┌── 合并分 ≥80% → 讲错题 → 写章节 wiki → 子Agent规划下一章
       判定 ────────┤
                    └── <80% → 重构教材为 v2 版（换个讲法）+ 新测验 → 重学
   ↓
本阶段最后一章通过 → 阶段总测验 → 询问是否进入下一阶段 → 循环
```

## 六类题型（这是它和普通 AI 教学的关键区别）

每个测验**强制**包含全部六类，且**选择+填空合计不超过 50%**：

| 题型 | 考什么 | 例子 |
|------|--------|------|
| **选择题** | 概念辨识 | "commit 本质是？A.diff B.快照…" |
| **填空题** | 精确回忆 | "git _____ 把暂存区提交到仓库" |
| **实战题** | 真能做出来 | "写出把 feature 分支3次提交合并到 main 的完整命令" |
| **模拟题** | 判断与取舍 | "同事 force push 覆盖了别人的提交，你会如何排查？" |
| **算法/推导题** | 第一性原理 | "推导 add+commit 时 Git 内部创建了哪些对象、如何引用" |
| **高难度综合题** | 跨章节综合 | "团队 PR 频繁冲突，给出诊断+策略+规则，说明取舍" |

> 绝不会出现"全是选择题"的敷衍测验。`quiz-types.md` 里的 floor rules 是硬约束。

## 评分机制

- **客观题**（选择/填空）：二元判定，对错分明。
- **主观题**（实战/模拟/算法/综合）：按维度 rubric 给部分分。例如实战题看「正确性 50% + 过程 35% + 边界处理 15%」。
- **章节通过线**：`0.45 × 章节测验 + 0.55 × 计划测验 ≥ 0.80`（计划测验是迁移检查，权重略高）。
- **批注写回文件**：AI 不会只在对话里报分数——**每道题的批注（题号/类型/对错/失分点，主观题附维度细分）会写回测验文档底部的「AI 批阅区」表格**。章节测验、计划测验、阶段总测验三类**全部写回**，不留对话-only 的盲区。你填的测验 = 你的答题 + AI 逐题批注，一份完整复盘资料。
  - 计划测验虽是现场逐题问答（不让你预填文件），但问答结束后 AI 会把整轮 Q&A + 讲评 + 批阅区整理写回 `plan-quiz.md`，复盘时和章节测验放在一起对照。
- **超纲题不计分（公平性核心）**：每道题都标了「考点: KP-x」，对应章节文档的「知识点清单」。**打分前 AI 会做覆盖度校验**——如果某题考点不在清单内（或清单里写了但章节没真正讲透），该题判为**超纲**，**从分母中剔除、不计入通过率**，并触发「补讲补考」：AI 把缺失的知识点补进章节文档（六要素完整），再出一道同型同分值的新题让你补答，这道补考题正常计分。**你永远不会因为章节没讲过的内容而无谓失分。**
- **失败处理**：最多重讲 3 次（v1→v2→v3），每次必须换讲法；v3 仍不过会如实告诉你需要外部补补，不死循环。

详见 `references/grading.md`。

## 章节讲解深度

为解决"类比很生动但概念很模糊""测验考了没讲的内容"两类问题，章节文档有两项硬要求：

1. **知识点清单（KP list）**：章节开头列出 4-8 个知识点（KP1、KP2…），每个对应一个核心概念。**这份清单是章节测验出题范围的唯一基准**——测验每题都标 `[考点: KP-x]`，不在清单里的内容不得作为计分题。生成测验的子 agent 必须自检覆盖度，主流程打分前还会再校验一次（双保险）。

2. **核心概念六要素**：每个核心概念必须六项齐全，缺一不可：
   | 要素 | 作用 | 缺失的后果 |
   |------|------|-----------|
   | ① 精确定义 | 公式/签名/语法，可查证 | 填空/算法题失分（题要精确值，脑子里只有类比） |
   | ② 直觉解释 | 类比/心智模型 | 概念难理解 |
   | ③ 最小例子 | 能跑/能验证的最小用例 | 不会用 |
   | ④ 推导或代码 | 逐步推导/逐行注释 | 只会背结论不会做 |
   | ⑤ 边界条件 | 何时适用/失效/极端情况 | 实战题失分 |
   | ⑥ 与相关概念对比 | 和易混淆概念的区别 | 选择题失分（辨析题） |

   类比是帮助理解的，但**永不替代精确定义和边界条件**——这是测验能拿分的基础。

## 图形化交互演示

有些概念文字讲不透——状态机的转换、缓存的新鲜/过期、算法的步骤推进、数据在区域间的流动。对这些，章节会生成**可交互的 HTML 演示**，让你点按钮/拖滑块直观看到。

**不是每个概念都画**——AI 对每个知识点按信号判定（有状态变化/有空间结构/有数据流动/参数敏感/静态易误解/算法步骤），**≥2 个信号才生成**。纯定义、纯语法不画，避免画蛇添足。一章 0-3 个演示都正常。

**演示特点**：
- **可交互**（不是静态图）：按钮控制步骤、滑块调参数、点击高亮节点——状态变化肉眼可见。
- **独立 html 文件**，存章节目录下的 `viz/` 子文件夹，**双击即可在浏览器打开**，无外部依赖、无需联网。
- 章节文档里用 `🖼️ 交互演示` 链接嵌入对应概念节，学到那一步就能点开。

**质量保障**：每个 html 生成后，主 agent 会跑 **JS 静态检查**（语法检查、元素存在性、未定义引用）——**有 bug 的演示绝不交付**，宁可丢弃改文字，也不给你一个打开就报错的页面。

## 阶段校验（阶段总测验）

每学完一个阶段（最后一章通过时），不是直接进下一阶段，而是先过一道**阶段总测验**门槛：

- **何时出现**：本阶段最后一章通过后自动生成（不在阶段开始时预生成，这样能针对本阶段累积的弱项重点考查）。
- **题量充足**：与章节测验（6-10题）不同，阶段总测验**每章至少 2-3 题、六题型每类至少 2 题**，4-6 章的阶段通常 12-18 题。这是你明确要求的——阶段门槛必须够分量。
- **网络数据增强（强制）**：阶段总测验**必须**先派子 agent 从权威源抓取真实素材，再据此出题。详见下方「网络数据与真实性」。
- **覆盖范围**：本阶段全部章节，且**至少 2 道跨章节综合题**。
- **针对性**：如果本阶段多章 wiki 都记录"用户在 X 上不稳"，阶段总测验会出一道 X 专题综合题。
- **通过线**：≥80%。不过的话，定位最弱章节进入重构流程，重新通过后再做 `stageN-total-quiz_v2.md`。
- **结果写回**：和章节测验一样，批注写回文档，对话里也会得到「阶段总测验得分 + 通过/未通过」结论。
- **通过后**：询问你是否进入下一阶段，**不自动推进**。

也就是说，整个学习路径是 **章节测验 → 计划测验 → 阶段总测验** 三重校验，任何一层不过都会回头补，不会"带病前进"。

## 网络数据与真实性保障

为避免 AI"自信地讲错"（过时 API、记错的默认值、臆造的函数签名），阶段总测验**强制**从网络权威源拉取真实素材来出题。

**接入点（按你的要求）**：
- ✅ **阶段总测验（强制）**：题量大、覆盖广，正是纯 AI 生成最容易出错的地方，必须走网络增强。
- ⚪ **章节教材（可选）**：涉及版本敏感事实（框架 API、命令参数）时，章节生成子 agent 可选拉取权威源补强例子；概念性内容可纯 AI 生成；网络失败不阻塞。
- ❌ 基线/章节测验/计划测验：不接入（题量小或需现场问答，网络化收益低）。

**真实性三道闸**（详见 `references/web-research.md`）：

| 闸门 | 要求 |
|------|------|
| **白名单源** | 只从官方文档/官方仓库/RFC/权威标准抓取（react.dev、kubernetes.io、git-scm.com、datatracker.ietf.org 等）。博客/Medium/SO 仅用于找线索，事实必须回溯到官方源。 |
| **时效性** | 快变主题（前端框架、云服务）优先 18 个月内的文档；无法判断时标 `recency:unknown` 谨慎对待。 |
| **交叉印证** | 行为性论断需 ≥1 官方源 或 ≥2 独立源（≥1 白名单）。纯定义只需官方源即可。 |

**每题标注出处**：用了网络素材的题目会带 `[出处: url]`，可点击核对；降级路径下未验证的题会标 `[未验证]` 提醒你查文档。文件末尾还有完整「引用源」列表。

**网络失败优雅降级**：网不通不了时不中断学习——回退到纯 AI 出题，但在测验顶部标注 `⚠️ 降级：本测验未经外部验证`，让你知道这轮的准确性可能偏低。**永不静默用 AI 记忆冒充已验证事实**；官方源与 AI 既有认知冲突时，**信官方源**。

## 学习路径规划（网络驱动，非 AI 臆造）

早期版本的总目录是 AI 凭记忆分阶段、凭记忆列章节——结果"规划有点乱"，可能漏掉公认核心知识点、顺序不合学习曲线、冷门领域知识过时。现已重构为**外部骨架 + AI 适配**：

**初始化时强制做的事**（按你的要求，路径 + 各章资料都拉）：
1. 基线批改后，派 **curriculum-research 子 agent** 从权威源拉取该领域的**公认学习路径**：
   - 官方学习路径（react.dev/learn、kubernetes.io 教程、docs.python.org 教程目录）
   - 公认路线图（roadmap.sh 等）
   - 权威书目录、ACM/IEEE 标准课程序列
   - 要求 ≥2 个独立白名单源交叉印证，取**共识结构**
2. 同步为**每章生成资料卡**（`plan/sources/stageN-chXX.md`），存官方要点/易错点/建议教学顺序，供后续章节生成直接引用，不必重复抓取。
3. AI 拿到外部骨架后，**只做适配不做架构**：按你的基线/目标水平拆分合并章节、补强前置缺口、调整深度——**每一处偏离原始路径都要写明理由**。

**总目录会明确标注**：每个阶段/章节带 `[出处: url]`（已验证）或 `[AI推断]`（无外部源），还有「适配说明」区列出所有调整及原因。你能清楚看到哪些是公认路径、哪些是为你定制的。

**AI 的边界**：禁止凭空发明与权威源矛盾的阶段结构。如果 AI 真觉得公认顺序有问题，必须给出具体教学理由并在总目录里**显著标注**供你质疑——而不是悄悄改掉。

**网络失败降级**：网不通时回退纯 AI 规划，但总目录顶部标注 `⚠️ 降级：未经外部学习路径验证`，每个未验证阶段标 `[AI推断]`，让你知道这份计划的可信度边界。

## 为什么用 HTML（交互式学习体验）

早期版本用 markdown 文档作答——用户得编辑 `**你的答案：** ___` 这样的原始文本，选择题还要手写字母，体验差且易错。现已全部改为 **HTML**：

**测验交互**（基线/章节/阶段总测验）：
- **选择题** → 单选/多选框，直接点选项
- **填空/实战/模拟/算法/综合题** → 输入框/文本域，直接打字
- 点底部「提交答案」→ 自动生成 `answers.json` 下载（底部也显示供复制）→ 在聊天告诉 AI「做好了」→ AI 读 json 批改
- 批改结果写回 HTML 底部的「AI 批阅区」，重开页面就能看到逐题对错+失分点

**教材/总目录**：排版精美、可折叠、可内嵌交互演示，比 markdown 原文易读得多。

**质量保障**：每个 HTML 生成后跑 JS 静态检查（语法/元素/未定义引用），不过则降级回 md——不会给你打不开的页面。

> **计划测验（plan-quiz）例外**：仍是 AI 在聊天里逐题提问（你答、它追问），事后写一份 md 收据。这是刻意保留的——现场问答查迁移能力，填表替代不了。
```

> 学习内容跟着项目走，不污染你的用户主目录。换项目学习不同主题，互不干扰。

## 目标水平三档

初始化时会确认你的目标水平，它**直接影响**计划深度：

| 你的说法 | 映射档位 | 计划特点 |
|---------|---------|---------|
| "了解"、"入门"、"能用一下" | `aware` | 少阶段、宽覆盖、综合题轻量 |
| "能独立解决实际问题"、"工作中用"（默认） | `practitioner` | 标准深度、实战为主、综合题要求设计方案 |
| "能教别人"、"面试通过"、"精通" | `expert` | 多阶段、推导/算法/综合占重、要求讲清取舍 |

## 常见疑问

**Q：中断后再调用，进度还在吗？**
在。`meta.json` 是状态机，再次用自然语言触发时会自动检测并接续。

**Q：学完一个主题想学新的怎么办？**
直接说新主题。如果当前目录已有别的主题的工作区，AI 会列出来让你选，不会搞混。

**Q：教材是"完整教学"还是"只给学习路径"？**
完整教学——读完章节就能直接做测验，不需要再找外部资料。

**Q：AI 既是出题人又是阅卷人，会不会放水？**
`grading.md` 专门写了反宽松偏见的规则：主观题按推理质量而非与标准答案的相似度打分；拿不准时取较低分并说明缺了什么。
