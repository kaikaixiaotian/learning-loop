02 核心概念

6. 值传递与引用语义（KP6）

  1. ① 精确定义
    • 总规则：Java 的实参→形参绑定只有值传递——调用方法时，实参的值被复制一份给形参。
    • 基本类型：复制的是数值本身。方法内改形参，实参不变。
    • 引用类型：复制的是引用值（地址）的副本。形参与实参指向同一个堆对象。
    • 引用传递（对照）：指「形参是实参的别名」。Java 不具备这种能力。
  2. ② 直观演示
    • 把场景切到「② sb = new …」，连点两次下一步：看堆上出现新对象 O2 后，f 栈帧的 sb 改指 O2，而 main 的 s 仍指向 O1。
    • 再切到「① sb.append()」走到最后一步：对比两种场景结束时 main 读到的内容。
    • 用「③ swap」验证 KP6·A5：交换的只是 f 栈帧里的两个副本槽。
  3. ③ 最小例子
    static void f(int n, StringBuilder sb) {
    n = 999;                              // 改副本：无效
    sb.append("!");                       // 沿副本找到同一对象：有效
    sb = new StringBuilder("新对象");     // 重赋值副本：无效
}
int a = 1;
StringBuilder s = new StringBuilder("hi");
f(a, s);
System.out.println(a + " " + s);          // 输出：1 hi!
  4. ④ 推导或代码
    1. 调用 f 时，JVM 为 f 新建栈帧：n ← a 的副本（1）；sb ← s 的副本（同一地址）。
    2. n = 999 只改 f 栈帧的 n 槽，main 的 a 不动。
    3. sb.append("!") 沿地址找到堆上唯一对象，内容变 "hi!"。
    4. sb = new … 让 f 栈帧的 sb 改指新对象——main 的 s 仍指旧对象。
    5. f 返回、栈帧销毁：a=1，s→"hi!"。变的永远是「参数指向的对象」，不是「实参手里的引用」。
  5. ⑤ 边界条件
    • swap 反证：swap(引用,引用) → 交换不生效。原因：交换的是两份地址副本，实参引用未被改写。
    • 数组同理：arr[0] = 9 → 生效；arr = new int[3] → 无效。原因：数组变量也是引用，规则与对象完全一致。
    • 传 null：形参拿到 null 副本，方法内 p = new … → 实参仍为 null。原因：重赋值只作用于副本。
    • String 的错觉：传 String「改不了」→ 并非传值方式特殊。原因：String 不可变，任何"修改"都是创建新对象+重赋值。
  6. ⑥ 与相关概念对比
    维度值传递（Java）引用传递（C++ &、C# ref）
    形参是什么实参值的副本实参的别名
    对形参重新赋值实参不变（只改副本）实参跟着变（同一存储）
    改指向对象的内容可见（副本指向同一对象）可见
    swap 能否实现不能（反证）能
🧪 检查点 · KP6（非计分，做完再往下）
Q1（预测）：static void g(StringBuilder b){ b = b.append("!"); } 调用 g(s) 后 s 的内容？先预测，再到上面演示的场景①里走一遍验证。
"hi!"。append 返回的是同一个对象（链式调用），b 指向没变；改的是堆上对象本身 → 对外可见。验证：演示场景①第 3 步。见 KP6·A3。
Q2（判断+说理由）：「方法里改了对象外面能看到，说明 Java 对象是引用传递。」这个说法对吗？
错。改字段可见只是「副本引用指向同一对象」的推论；判断依据是重新赋值和 swap 是否影响实参——它们都不影响，所以是值传递。见 KP6·A4 / A5。
Q3（填关键值）：void h(int[] a){ a = new int[]{7}; } 调用后，外部数组的第 0 个元素是原来的值还是 7？_____
原来的值。重赋值只改形参副本（KP6·A4）；若写 a[0] = 7 才会生效（KP6·A3）。
